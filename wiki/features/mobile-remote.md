# Mobile Remote 📱

PowerX Keys includes an **embedded HTTP server** that turns any phone on the same WiFi network into a wireless macro remote control. The server serves a full mobile web UI directly from the app — no external apps required.

## Overview

- Embedded `HttpListener` server on port 8745
- PIN-based authentication with brute-force lockout
- Full mobile web UI served as inline HTML
- Optional internet access via Cloudflare Tunnel
- Soundboard: upload, play, and manage audio from phone

## Architecture

`RemoteServerService` is a **singleton** (`RemoteServerService.Instance`) that:

1. Starts an `HttpListener` on `http://+:{port}/`
2. Falls back to `http://localhost:{port}/` if no admin URL ACL
3. Serves a complete mobile web page at `/` (generated by `GetMobilePageHTML()`)
4. Handles API requests on background threads via `Task.Run`

## Authentication

### PIN System
- Default PIN: `1234` (configurable in settings)
- `POST /api/auth` validates the PIN
- Success: returns `{"ok":true}`, plays a PC feedback sound, shows tray notification
- Failure: increments counter, locks out after **3 failed attempts** for 30 seconds

### Security
- Brute-force lockout: `_isLockedOut` flag + `_lockoutEndTime`
- Returns HTTP 429 during lockout with `wait` seconds remaining
- No persistent sessions — PIN is re-verified each connection

## Volume Control

Uses **COM interop** with Windows Core Audio API:
- `IMMDeviceEnumerator` → `IMMDevice` → `IAudioEndpointVolume`
- Gets/sets `MasterVolumeLevelScalar` (0.0–1.0)
- No external dependencies — pure Win32 COM

## Controller (Remote Mouse & Keyboard)

The `/controller` (and `/control`) endpoint serves a separate HTML page (`remote_controller.html`) for remote desktop control:
- **Screenshot capture**: GDI-based screen grab -> JPEG compression
- **Click simulation**: P/Invoke `SetCursorPos` + `mouse_event`
- **Pinch-to-zoom**: Up to 5.0x zoom on screenshots
- **Modifier key locking**: Persistent Ctrl/Alt/Shift/Win states
- **Trackpad Double-Tap and Hold to Drag**: Double-tapping and keeping finger on the trackpad locks the left click down for dragging, and lifting the finger releases it.

## Cloudflare Tunnel

For access outside the local network:
- Downloads `cloudflared.exe` on first use to `%LOCALAPPDATA%/PowerX_Keys/`
- Creates a temporary `trycloudflare.com` URL
- Parses the URL from cloudflared's stderr output
- `ActiveUrl` property returns tunnel URL when available, local URL otherwise

## Soundboard

- Sounds stored in `%LOCALAPPDATA%/PowerX_Keys/Soundboard/`
- Metadata: `soundboard.json` (JSON array of `{id, name, emoji, color, file}`)
- File size limit: 5MB
- Playback: WPF `MediaPlayer` on the UI thread
- Toggle behavior: clicking a playing sound stops it

### UX Design: Long-Press → Edit Bottom Sheet

The interaction pattern is **long-press** (press and hold ~700ms) on any macro button, which vibrates the phone and slides up a **bottom sheet** with all edit options.

**Bottom Sheet Contents:**
```
┌─────────────────────────────┐
│  ✏️ Customize Button         │
│                             │
│  🎭 Emoji:  [emoji chips]   │
│  🖼️ Image:  [Upload Photo]  │
│  🎨 Color:  ● ● ● ● ● ●     │
│  ✏️ Name:   [text input]    │
│  👁️ Show Name:  [toggle]   │
│                             │
│  [Cancel]      [Save]       │
└─────────────────────────────┘
```

**Behavior:**
- Long-press triggers a subtle haptic buzz + the sheet slides up
- If the user sets a custom image, it replaces the emoji
- Clearing the image falls back to the emoji icon
- All customizations are saved per-button and synced server-side

### Data Storage

Saves customizations server-side in a JSON file at `%LOCALAPPDATA%/PowerX_Keys/Remote/customizations.json`. All connected phones see the same customizations. Custom images are uploaded via multipart form POST to `/api/macro/image/{id}` and saved under `%LOCALAPPDATA%/PowerX_Keys/Remote/Images/`.

### Implementation Details

- **GET `/api/macros`** returns `{ id, name, icon, color, customImage, showName, size, enabled }`
- **POST `/api/macro/customize`** updates button properties (name, icon, color, showName, size)
- **POST `/api/macro/image/{id}`** uploads button custom image
- **GET `/api/macro/image/{id}`** serves button custom image (with timestamp versioning `?t=...` to bypass caching)
- **DELETE `/api/macro/image/{id}`** deletes custom image

## Button Sizing 📐

> **Status:** Completed ✅ (Implemented 2026-06-06)

Each button can be set to one of three sizes:
- **1×1** (default) — standard single cell
- **2×1** (wide) — spans 2 columns
- **2×2** (big) — spans 2 columns and 2 rows

Size can be changed via:
- The **edit bottom sheet** (size selector buttons)
- The **Quick Actions Ring** (📐 option cycles sizes instantly)

Stored per-button in `MacroCustomization.Size`, persisted server-side.

## Drag & Drop Reordering 🔀

> **Status:** Completed ✅ (Implemented 2026-06-06)

Buttons can be rearranged by entering **reorder mode** (via Quick Actions Ring → 🔀 Move):
- Buttons shake with a subtle animation to indicate reorder mode
- Long-press and drag a button over another to **swap** their grid positions
- A ghost clone follows the finger during drag
- Drop target highlights with a purple dashed border
- Swap auto-saves via `/api/grid/save`

## Pages (Stream Deck Style) 📄

> **Status:** Completed ✅ (Implemented 2026-06-06)

Multiple pages of macros, like Stream Deck / Touch Portal:
- **Page indicator dots** at the top (● ● ○) — tap to switch
- **Arrow buttons** (‹ ›) for previous/next page
- **Swipe left/right** gesture to change pages (60px threshold)
- **+ button** to add new pages

### API:
- `POST /api/grid/save` — now accepts `pageIndex` parameter
- `POST /api/grid/page/add` — creates a new empty page
- `POST /api/grid/page/remove` — removes a page by index (cannot remove last page)

## Launchpad Grid System 🎛️

> **Status:** Completed ✅ (Implemented 2026-06-05)

### Concept

Instead of the old behavior where the PC pushes macros as a flat list, the remote page shows a **pre-built empty grid** — like a Stream Deck. Users build their own dashboard by tapping empty slots and assigning macros.

- **Old behavior:** PC sends macros → phone renders them in order → no layout control.
- **New behavior:** Phone shows an empty grid of customizable rows/columns → user taps "+" slots → picks which macro goes where.

### Visual

```
┌──────┐  ┌──────┐  ┌──────┐
│  ⚡  │  │  🎮  │  │  +   │   ← assigned, assigned, empty
│ Build│  │ Game │  │      │
└──────┘  └──────┘  └──────┘
┌──────┐  ┌──────┐  ┌──────┐
│  +   │  │  🔇  │  │  +   │   ← empty, assigned, empty
│      │  │ Mute │  │      │
└──────┘  └──────┘  └──────┘
        [ + Add Row ]
```

### Behavior

- Empty slots show a dashed border with a "+" icon
- Tapping an empty slot opens a **macro picker** (list of available mobile-enabled macros from PC)
- User chooses position, leaving gaps for visual grouping if desired
- Grid columns follow the existing grid size setting (2×, 3×, 4×) saved in phone's `localStorage`
- Rows are **flexible** — user can add/remove rows via "+ Add Row" and "- Remove Row" buttons at the bottom of the grid
- Long-press an assigned slot → opens the edit bottom sheet where they can customize or tap **Remove from Grid** to clear the slot
- Layout mapping (`grid`) and row count (`gridRows`) are saved server-side on the PC inside `customizations.json` to keep all connected devices in sync

### Data Sync & Backend Upgrades
- **RemoteConfig Data Model:** Multi-page architecture with per-button customization:
  ```csharp
  public class MacroCustomization
  {
      public string Name, Icon, Color, CustomImage;
      public bool ShowName = true;
      public string Size = "1x1"; // "1x1", "2x1", "2x2"
  }

  public class RemotePage
  {
      public string Name = "Page 1";
      public Dictionary<string, string> Grid = new();
      public int GridRows = 4;
  }

  public class RemoteConfig
  {
      public Dictionary<string, MacroCustomization> Buttons = new();
      public List<RemotePage> Pages = new();
  }
  ```
- **Automatic Migration:** Detects legacy single-page format and auto-migrates to multi-page structure.
- **GET `/api/macros`:** Returns macros, `pages[]` array, and backward-compat `grid`/`gridRows` for first page.
- **POST `/api/grid/save`:** Accepts `pageIndex`, `grid`, `gridRows` to save a specific page.

## Design Decisions 📋

> Key decisions made during development discussions.

| Decision | Details |
|----------|--------|
| 🚫 **No image-by-URL** | Rejected adding images via URL link for security reasons (could load malicious/inappropriate content) |
| 📱 **Auto image sizing** | Custom images auto-fit to button — no manual stretch/crop options needed |
| 📳 **Haptic feedback** | Must have a trigger and can be disabled through settings |
| 🎮 **Radial wheel default** | Circular wheel is the default long-press style, but users can switch to classic bottom sheet from settings |
| 📂 **Folders delayed** | Grouping/folders feature delayed — pages cover the immediate need |
| 💰 **Subscription model** | Plan to move from free → subscription in the future; icon packs would be created from scratch and included as premium content |
